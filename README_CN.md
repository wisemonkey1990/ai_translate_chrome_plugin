# AI 网页翻译 Chrome 插件

[English](README.md) | 简体中文

本仓库发布的是一个基于上游项目修改和扩展而来的 Manifest V3 Chrome 网页翻译扩展，使用用户配置的 OpenAI 兼容大语言模型 API 进行翻译。

> **上游来源与致谢**：本项目并非原创项目，基于 [jxzhangaoran/ai_translate_chrome_plugin](https://github.com/jxzhangaoran/ai_translate_chrome_plugin) 参考和扩展而来。本仓库的工作主要包括通信修复、翻译性能优化、后台进度、导出工具、缓存管理、测试与开源文档完善。本仓库与上游项目及其作者不存在隶属、合作或背书关系。

本仓库发布的是上述上游项目的修改版衍生作品，不是独立原创实现。这里的改动以独立提交维护；再次分发前，请同时审阅上游项目，并遵守其可能适用的许可证、署名要求及第三方 API 服务条款。

## 功能亮点

- 一键翻译当前网页。
- 点击翻译后关闭弹窗，翻译任务仍在后台继续。
- 单个翻译单元完成后立即写回页面，边翻译边呈现。
- 优先翻译视口附近内容，让首屏更快显示译文。
- 最多 6 路并发请求，遇到限流或服务端错误时自动退避并降低并发。
- 合并相邻短文本节点，复用相同文本的进行中请求，减少 API 调用。
- 网页内容总结异步执行，不阻塞前几个节点的翻译。
- 页面右下角浮动工具栏，可切换原文/译文或下载对照文件。
- 自动清理模型返回的 `<think>...</think>` 等常见思维链标签。
- 支持配置 API 地址、模型、Temperature、格式保留、网页总结和系统提示词。
- 本地缓存翻译结果，支持设置 1-10 MB 容量上限和 30 天有效期。
- 设置页显示缓存占用，并提供一键清空翻译缓存。

## 安装

当前以“加载已解压的扩展程序”方式使用。

1. 克隆或下载本仓库。
2. 在 Chrome 或 Chromium 浏览器中打开 `chrome://extensions/`。
3. 开启**开发者模式**。
4. 点击**加载已解压的扩展程序**。
5. 选择本仓库目录。

修改源码后，点击扩展卡片上的**重新加载**；测试 content script 相关修改时，还需要刷新网页。

## 配置

打开扩展弹窗，点击**设置**，配置以下项目：

- **API Base URL**：OpenAI 兼容 API 的基础地址，不要重复添加末尾的 `/chat/completions`。
- **模型名称**：由 API 服务商支持的模型名称。
- **API Key**：存储在 Chrome 扩展存储中，不会写入本仓库。
- **Temperature** 和格式保留选项。
- **启用网页内容总结**：可选的上下文总结功能；它与翻译并行执行，不会阻塞首批翻译。
- **系统提示词**：可选的翻译规则和风格说明。
- **翻译缓存容量上限**：可设置为 1-10 MB。

扩展会把网页文本发送到用户配置的 API 地址。请只使用自己信任的 API 服务和模型。

## 使用方法

1. 打开允许运行 content script 的网页。
2. 打开扩展弹窗并选择目标语言。
3. 点击**翻译页面**。
4. 翻译启动后弹窗会自动关闭，任务继续在页面后台运行。
5. 通过页面浮动进度条或扩展图标角标查看进度。
6. 翻译完成后，使用浮动工具栏切换**查看原文/查看翻译**，或点击**下载对照**。

扩展无法运行在 `chrome://` 等浏览器内部页面和 Chrome 网上应用店页面。翻译本地文件时，需要在扩展详情页开启**允许访问文件网址**。

## 性能设计

- **视口优先**：可见和临近视口的翻译单元优先进入队列。
- **翻译单元**：同一父元素下相邻的直接文本节点会合并，单元上限为 200 字符。
- **进行中请求去重**：相同文本共享同一个未完成请求。
- **持久化缓存**：刷新页面或重新打开浏览器后，成功结果仍可复用。
- **自适应并发**：遇到 429 或 5xx 时降低并发并指数退避，API 恢复后再恢复并发。
- **渐进式渲染**：每个翻译单元返回后立即更新 DOM。

## 项目结构

```text
manifest.json                     Chrome 扩展清单（MV3）
src/shared/                       各运行环境共用：常量、chrome.storage 封装、界面多语言、翻译缓存
src/background/service-worker.js  MV3 service worker：消息路由、进度角标
src/background/llm-client.js      /chat/completions 调用、重试、思维链标签清洗
src/background/prompts.js         翻译与页面总结提示词
src/content/                      Content script，按 manifest.json 中的顺序加载：
  state.js                          页面级翻译状态
  dom-text.js                       DOM 扫描、翻译单元合并、视口优先排序
  dom-apply.js                      写回译文、原文/译文切换
  page-ui.js                        进度条、浮动工具栏、对照下载、提示
  translation-queue.js              自适应并发队列（限流降速）
  translator.js                     翻译流程编排（缓存、去重、页面总结）
  main.js                           响应弹窗消息
src/popup/                        扩展弹窗和翻译控制
src/options/                      设置页和缓存管理
tests/                            Node 回归测试
```

## 开发与测试

无需安装依赖（需 Node.js 22+）。在仓库根目录运行：

```bash
npm test
```

该命令会对所有源码做语法检查，并运行 `tests/*.test.js`。测试会把真实源码文件加载到 Node 的 `vm` 上下文中执行，加载方式与 Chrome 加载普通脚本一致。测试覆盖思维链标签清理、请求重试、提示词、界面多语言、文本单元合并、视口排序、自适应并发队列、翻译缓存和对照导出。浏览器相关功能需要在 Chrome 中加载未打包扩展后手动验证。

源码是不经构建的普通脚本：同一运行环境中的文件共享全局作用域，所以加载顺序很重要。Content script 的顺序由 `manifest.json` 决定，service worker 由 `importScripts` 决定，弹窗和设置页由 `<script>` 标签决定。

## 隐私与安全

- 源码中不包含任何硬编码 API key。
- API Key 和用户设置存储在 Chrome 扩展存储中。
- 翻译请求只发送到用户配置的 API Base URL。
- 只有用户主动点击翻译后，扩展才会处理网页内容。
- 翻译缓存保存在本地 `chrome.storage.local`，可在设置页清空。
- 由于扩展使用 `<all_urls>` 权限，安装前请审阅源码并确认 API 配置可信。

## 已知限制

- API 服务需要兼容 OpenAI `/chat/completions` 接口格式。
- 翻译质量、速度和限流策略取决于所选模型及 API 服务商。
- 翻译开始后新增的动态内容不保证会自动翻译。
- DOM 行为高度定制的复杂网页可能需要针对站点进一步适配。
